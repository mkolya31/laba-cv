# Публикация на Ubuntu

Сборка выполняется в CI на Node.js 24; передаётся только `out/`. Для однократных серверных скриптов нужен Node.js 24, постоянно работающего сервиса нет.

## Первоначальная настройка

1. Подтвердить домен (пока `dev.kolyach.me`), DNS, путь `/srv/kolyach-dev` и существующие сайты VPS.
2. Создать отдельного пользователя доставки и каталоги `releases`, `shared`, `tools` внутри `/srv/kolyach-dev`. Дать пользователю запись только в дерево этого сайта, nginx — чтение публичных файлов.
3. В `tools` скопировать `scripts/generate-runtime.mjs`, `scripts/activate-release.mjs` и `src/lib/runtime.ts`, сохраняя структуру. Скриптам не нужны npm-зависимости.
4. Вне публичных каталогов создать файл окружения с правами 600. Образец ниже фиктивный. Реальные данные не добавлять в git, CI или логи.

```sh
CONTACT_PHONE=+15555550123
CONTACT_TELEGRAM_URL=https://t.me/example_user
RESUME_URL=/resume.pdf
```

Загрузить окружение и сформировать конфигурацию:

```sh
set -a
. /home/deploy/site.env
set +a
node /srv/kolyach-dev/tools/scripts/generate-runtime.mjs /srv/kolyach-dev/shared
```

Если `RESUME_URL` отсутствует или пуст, используется `/resume.pdf`. Допустим внешний HTTPS-адрес PDF без авторизации; тогда локальный PDF не нужен. JSON содержит только `phone`, `telegramUrl`, `resumeUrl`. Файл окружения не раздаётся nginx.

5. При локальном PDF загрузить документ в `shared/resume.pdf`, проверить открытие и права чтения nginx. PDF не помещать в проект или git.
6. Настроить DNS, получить сертификат HTTPS и адаптировать `deploy/nginx.conf`. Выполнить `sudo nginx -t`, затем reload nginx. Проверить остальные сайты.
7. В GitHub Environment `production` задать `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KEY`, `DEPLOY_KNOWN_HOSTS`. Host key сверить через доверенный канал. Контакты в GitHub Secrets не нужны.
8. Push в `main` запускает проверки и доставку. До первого деплоя установить tools и заполнить shared. При ошибке проверки, передачи или preflight текущий релиз не переключается.

## Изменение контактов или ссылки резюме

Изменить окружение и повторить запуск генератора. Пересборка не нужна. При ошибке прежний JSON сохраняется. При следующем открытии страницы используется новая конфигурация.

## Замена локального PDF

Загрузить через SFTP `resume.new.pdf` в `shared`, проверить файл и права чтения, затем переименовать в том же каталоге:

```sh
mv /srv/kolyach-dev/shared/resume.new.pdf /srv/kolyach-dev/shared/resume.pdf
```

Не удалять старый файл перед заменой. Незавершённая загрузка оставляет его доступным. Не нужны сборка, коммит, CI/CD и reload nginx. Новый запрос получает новую редакцию; открытая вкладка сама не обновляется. Кеш внешнего сервиса управляется этим сервисом.

## Откат и очистка

Выбрать предыдущий идентификатор из каталога `releases` и выполнить:

```sh
node /srv/kolyach-dev/tools/scripts/activate-release.mjs /srv/kolyach-dev PREVIOUS_RELEASE_ID
```

Меняется только ссылка `current`. PDF, окружение и runtime-конфигурация сохраняются. Очистку выполнять вручную только внутри `releases` после проверки абсолютных путей; не удалять текущий релиз, shared, tools или окружение. При первой публикации без предшественника отключается только новый virtual host.

## Приёмка

Проверить HTTPS, редирект HTTP, сертификат, соседние сайты, JSON и выбранный PDF без авторизации. Проверить четыре кейса перед резюме, новую вкладку и прокрутку, контакты, замену PDF одинакового размера, изменение RESUME_URL и сохранность shared после деплоя и отката. Записать результаты в `docs/verification.md`.
