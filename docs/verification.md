# Локальная проверка

Проверено 15 ноября 2026 года на Windows, Node.js 24.14.1, браузер Microsoft Edge через Playwright.

- Чистая установка `npm ci` выполнена.
- Production-экспорт Next.js собирается, TypeScript проходит.
- Браузерные smoke-проверки: кейсы до резюме, два способа связи из фиктивного JSON, внешний PDF и ошибка загрузки конфигурации, новая вкладка, шестисекундная смена фраз, ручной выбор и ожидание 30 секунд, сохранение остановки при фокусе, сокращённое движение.
- Ширины 360/768/1440 px: все фразы перебраны без смещения следующего раздела и горизонтальной прокрутки.
- Удвоенный размер текста на 360 px и чтение без JavaScript проверены автоматически.
- Снимки production-страницы на 1440 и 360 px просмотрены: декоративные полосы и смешивание поверх портрета удалены, лицо видно полностью.
- Генератор проверен на фиктивных данных: default /resume.pdf, внешний HTTPS-адрес, отклонение небезопасной ссылки, сохранение прежнего JSON при ошибке и отсутствие посторонних переменных в выводе.
- Переданный PDF проверен чтением pypdf: 3 страницы; файл не скопирован в проект. Срок SberUnity уточнён автором: 3 месяца от идеи до прототипа.

## Требует проверки на VPS

Домен и серверный доступ пока не предоставлены. Не проверены реальные HTTPS/DNS/сертификат, контакты, открытие выбранного PDF по публичному адресу, соседние сайты, права пользователя доставки, фактический запуск GitHub Actions, передача сборки, переключение и откат релиза на Linux. Публичная доступность GitHub-репозитория отдельно не подтверждена. Соответствующие задачи OpenSpec не считаются завершёнными.

Скрипты, workflow и nginx-конфигурация подготовлены; их наличие не заменяет проверки опубликованного сайта.

## Правила публикации из production

Проверено локально 15 ноября 2026 года:

- YAML workflow разобран; выполнена проверка реального Bash-шага для 11 разрешённых и запрещённых имён веток, включая пустые имена после `release/` и `hotfix/`.
- Проверены условия jobs для merge в production, закрытия без merge, merge в другую ветку, открытия PR и прямого push.
- Проверены зависимости deploy от production-source и verify, выбор merge_commit_sha и передача одного и того же артефакта из verify в deploy.
- ESLint, проверка форматирования и строгая валидация OpenSpec пройдены.

Защита ветки и ограничения environment в GitHub не настроены и не проверены: GitHub CLI возвращает HTTP 401 Bad credentials. До выполнения пункта 6.12 workflow отклоняет недопустимый источник перед деплоем, но не обеспечивает запрет самого merge. Фактический запуск workflow после merge на GitHub и доставка на VPS требуют отдельной проверки.

## Локальная реализация контейнерной доставки

Проверено 16 ноября 2026 года. VPS не изменялся.

- Подготовлены отдельный Compose сайта, внутренний HTTP nginx, HTTP/ACME bootstrap-конфиг gateway и HTTPS-конфиг. Compose валиден; все три nginx-конфига прошли `nginx -t` в Linux-контейнере. Для локальной проверки TLS использован временный самоподписанный сертификат из игнорируемого `.local`, не сертификат VPS.
- nginx закреплён digest `sha256:5616878291a2eed594aee8db4dade5878cf7edcb475e59193904b198d9b830de`. Тестовая среда — Docker Desktop Linux, Node.js 24 в контейнере; текущие образы проверены локально.
- Linux-интеграция проверяет реальные read-only mounts: переключение `live/current` без рестарта nginx, атомарную замену JSON и PDF одинакового размера, сохранность постоянных данных после отката, доступ к старым JS/CSS, отказ на отсутствующий или нечитаемый ресурс и коллизию assets.
- Проверены изменённый входной файл без частично опубликованного ресурса, повтор того же запуска, отказ устаревшего CI после отката, сериализация блокировкой, возврат после postflight-ошибки, явная ошибка неуспешного возврата и восстановление pending-журнала.
- Очистка сохраняет пять последних успешных и текущий релиз, не удаляет старые assets/shared и отклоняет symlink, ведущий за пределы каталога релизов.
- ESLint, Prettier, TypeScript и два runtime unit-теста прошли. Production-сборка прошла вне Windows sandbox после EPERM в sandbox. Семь браузерных тестов прошли в Edge на отдельном порту 43127; порт 3000 занят другим процессом, он не останавливался.
- Workflow доставляет артефакт со SHA, номером запуска и попыткой, использует `/opt/node24/bin/node`; Linux-интеграция добавлена перед загрузкой артефакта.

Не выполнены реальный GitHub Actions run, публикация коммита, защита ветки и Environment (GitHub CLI повторно вернул 401 Bad credentials), серверные пользователи/права/Node.js, сертификат, контейнер и первый публичный деплой. Для серверных шагов требуется административный доступ и реальные контакты/выбранный PDF от автора. Эти задачи остаются незавершёнными; локальные тесты не заменяют приёмку VPS.

## Настройки GitHub через браузер

16 ноября 2026 года подтверждена действующая браузерная сессия владельца репозитория. Ветка `production` уже существовала к началу этого этапа.

- Создано classic branch protection rule для `production`: обязательный PR без требования отдельного ревьюера, обязательный `verify` от GitHub Actions, актуальность PR, запрет обхода администраторами. Force push и удаление не разрешены. GitHub подтвердил сохранение правила.
- Для Environment `production` выбраны Selected branches and tags и единственное правило типа Branch с точным именем `production`. GitHub подтвердил: 1 branch and 0 tags allowed. Environment secrets пока отсутствуют.
- `production-source` пока нельзя выбрать как required check: новый workflow ещё не опубликован и check отсутствует в списке репозитория. Задача 6.12 остаётся незавершённой до добавления этого check и проверки запретов.
- Прямой SSH-доступ Git к GitHub не прошёл проверку publickey; HTTPS dry-run также сообщил о недействительных сохранённых учётных данных. Начат отдельный стандартный браузерный вход GitHub CLI; секреты и одноразовые коды в этот документ не записываются.

До завершения авторизации и публикации нового workflow ограничение исходной ветки PR ещё не обеспечено required check. Сохранённая защита и ограничение Environment не означают, что сайт уже опубликован или что VPS подготовлен.

Браузерная авторизация GitHub CLI завершена, вход под владельцем подтверждён. Старые сообщения 401 выше описывают состояние до восстановления доступа. Публикация нового workflow и добавление production-source выполняются следующим шагом.
