# Design

## Context

Мотивация — в `proposal.md`. Компонент `src/components/PhraseSwitcher.tsx` использует `setTimeout` с обычной задержкой `6000` и отдельным расчётом остатка ожидания `30000` после ручного выбора. Эффект останавливает таймер при наведении, фокусе, скрытой вкладке и сокращении движения. Анимация и резерв высоты находятся в CSS и не зависят от обычной задержки.

В `tests/site.spec.ts` есть проверки виртуального времени с `fastForward(6000)` и последовательными `runFor(6500)`. Последние после ускорения будут накапливать лишние переходы, поэтому механическая замена только `6000` недостаточна.

## Goals / Non-Goals

**Goals:** Локально изменить обычную задержку и проверить наблюдаемые временные границы средствами существующего Playwright Clock.

**Non-Goals:** Переписывать эффект, вводить новые настройки, зависимости или механизм таймеров. CSS и содержимое фраз не требуют изменений.

## Decisions

1. Заменить обычную задержку на `4000` в существующем эффекте. Расчёт `30000 - (Date.now() - lastManual.current)` сохранить: он определяет первый переход после ручного выбора, а не обычный интервал. Альтернатива — менять все тайминги пропорционально — противоречит ограниченному запросу issue.
2. Проверять время небольшими последовательными шагами с `page.clock.runFor`: 3999 + 1 мс для обычного перехода, 29999 + 1 мс после ручного выбора. Синхронизировать начало измерений с готовностью клиентского компонента, явно разрешить движение, убрать указатель и фокус перед измерениями. Для полного цикла проверять результат каждого интервала 4000 мс; не заменять существующие 6500 мс на произвольный запас, который накопится. Альтернатива — реальные ожидания — замедляет проверки и делает их зависимыми от нагрузки.
3. Ввести отдельное требование в `profile-presentation`, поскольку основной спецификации ещё нет. Предыдущие delta содержат конфликтующие 6 секунд: `build-resume-mvp` — автоматическая смена, возобновление и снятие остановки; `add-fullstack-carousel-phrase` — сценарий автоматического перехода. При последующей синхронизации сначала перенести эти capability, затем согласовать все эти места с 4 секундами и сохранить остальные требования. Архивирование этого изменения до согласования создаст противоречивую основную спецификацию. В рамках текущего предложения предыдущие артефакты не редактируются.

Существующие Next.js, React, TypeScript и Playwright позволяют выполнить итерацию небольшой локальной правкой без изменения архитектуры; задачи укладываются в бюджет MVP 48 часов.

## Risks / Trade-offs

- Проверка может измерять время до готовности клиентского эффекта или случайно удерживать фокус → установить виртуальные часы до открытия страницы, дождаться готовности компонента и явно задать условия автосмены.
- Устаревшие шаги `6500` пропустят промежуточную фразу → проверять каждую границу нового интервала отдельно.
- Старые delta возвращают 6 секунд при синхронизации → согласовать перечисленные требования и сценарии после переноса предыдущих изменений.

## Migration Plan

После реализации выполнить проверки проекта и production-сборку; публикация — через существующий процесс merge в `production`. После публикации проверить автосмену на реальном сайте и доступность ссылок. Отдельная миграция конфигурации не нужна. Откат — возврат изменения через обычный процесс проекта и повторная доставка.
