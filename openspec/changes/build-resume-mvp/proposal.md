# Proposal

## Why

Максиму Коляченко нужен сайт, который можно отправить заинтересовавшемуся руководителю R&D-команды лаборатории кибербезопасности Сбера вместо обычного сопроводительного сообщения. Команда разрабатывает агента проверки ПО, а разработчик нужен для ускорения фронтенда; сайт должен показать качество интерфейса, самостоятельность и результаты работы Максима, помогая обосновать стоимость его услуг.

## What Changes

- Создать русскоязычную адаптивную страницу экосистемы kolyach.me на dev.kolyach.me. Формального текста вакансии нет; основание для позиционирования — описание команды и её потребности со слов автора.
- Взять за визуальный ориентир предоставленный макет: тёмный фон, крупный портрет, красные и янтарные акценты, диагонали и заголовок «Я …». Имя и роль видны постоянно; фразы переключаются автоматически и вручную.
- Разместить перед первым переходом к полному резюме четыре кратких кейса: mini-CRM семейного магазина, архитектура подпроцесса подтверждения операций, библиотека подготовки фронтенд-дистрибутива к релизу, обязательная для разработки прикладного модуля в СБОЛ.про и используемая 300+ командами, и прототип SberUnity.
- После кейсов показать приглашение изучить полное резюме и связаться, ссылку на документ, действия «Позвонить мне» и «Написать в телеге».
- Рассказать о фактически использованных технологиях и публикации сайта; добавить ссылку на исходный код на GitHub.
- Использовать React + Next.js, статическую сборку, nginx на Ubuntu VPS и автоматическую доставку через GitHub Actions после merge PR в `production` из `develop`, `release/*` или `hotfix/*`, с обязательными проверками и защитой ветки от других источников и прямых push. Бюджет первого релиза — до 48 часов разработки с последующими итерациями.
- Интегрировать сайт в существующий Docker-gateway VPS по согласованному [предложению](../../../docs/vps-integration-proposal.md): отдельный nginx-контейнер в сети `web`, HTTPS и ACME на общем gateway, без новых публичных портов. Сборка выполняется только в CI; Node.js 24 на VPS используется для однократных серверных скриптов.
- Ограничить CI каталогами этого сайта; переключать релиз после preflight с защитой от конкурирующих и устаревших запусков, проверять опубликованную версию и откатывать неуспешную публикацию. Сохранять хешированные ресурсы старых страниц и последние пять успешных релизов.
- Телефон, Telegram и ссылка на резюме задаются переменными окружения на VPS. Серверный скрипт формирует отдельный публичный JSON; браузер загружает его после открытия страницы. Значения не включаются в репозиторий, сборку и артефакты CI. Кнопкам связи и ссылке на резюме нужен JavaScript; остальное содержимое доступно и без него.
- `RESUME_URL` задаёт ссылку на PDF-резюме: по умолчанию `/resume.pdf`, также допустим внешний HTTPS-адрес без авторизации. При внешнем адресе локальный PDF необязателен. Для локального варианта nginx отдаёт файл из отдельного каталога вне сборок: замена не требует пересборки, коммита, CI/CD или перезапуска сервисов; деплой и откат сохраняют документ. Финальная фотография, выбранное резюме, контакты на VPS, URL репозитория, домен и доступ для публикации являются входными материалами.
- Вне MVP: Python/FastAPI, база данных, CMS, формы отправки сообщений, отдельные страницы кейсов, интерактивные демонстрации проектов, HTML-версия полного резюме и сложные декоративные анимации. Подключение аналитики отдельно не согласовано и в этот релиз не входит.

## Capabilities

### New Capabilities

- `profile-presentation`: представление автора, смена фраз, адаптивная композиция и доступное чтение страницы.
- `experience-cases`: четыре кейса с точным разделением личного вклада и командных результатов.
- `resume-and-contact`: переход к полному резюме после кейсов, телефон, Telegram и ссылка на исходники.
- `site-publishing`: воспроизводимая сборка, проверки и публикация статического сайта через существующий Docker-gateway Ubuntu VPS с безопасным обновлением и откатом.

### Modified Capabilities

Нет: действующих спецификаций проекта пока нет.

## Impact

Приложение и базовый workflow уже реализованы; потребуются Compose нового сайта, отдельные конфигурации внутреннего nginx и gateway, доработка активатора, workflow и инструкции публикации. На VPS нужны отдельный пользователь доставки, администратором управляемая Node.js 24 и каталоги релизов, постоянных данных и хешированных ресурсов. Существующие ESLint и Prettier через `@kolyach/eslint-config` сохраняются. Публичный API и постоянно работающий процесс Node.js не нужны. Изменения общего gateway ограничиваются новым virtual host и сертификатом; миграция других проектов и исправление существующего 502 у 2popuga.kolyach.me в объём не входят.
