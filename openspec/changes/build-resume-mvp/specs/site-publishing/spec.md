# Spec Delta

## Purpose

Обеспечить воспроизводимую проверку и публикацию сайта на выделенном домене Ubuntu VPS, чтобы руководитель мог открыть рабочую страницу, а автор — безопасно обновлять её через GitHub.

## ADDED Requirements

### Requirement: Воспроизводимая проверенная сборка

Проект SHALL предоставлять документированные команды чистой установки зависимостей, lint, проверки форматирования, типов и production-сборки. Сборка SHALL формировать полный набор статических файлов страницы и локальных ресурсов, пригодный для раздачи веб-сервером без Python-бэкенда.

#### Scenario: Чистое окружение

- **WHEN** в поддерживаемой документированной среде выполняются установка по lock-файлу и команды проверок
- **THEN** проверки завершаются успешно и создаётся набор файлов страницы с портретом и загрузкой `resumeUrl` из runtime-конфигурации; реальный PDF и серверное окружение не требуются для сборки и не включаются в её артефакт

### Requirement: Проверка изменений до публикации

Для pull request и обновлений основной ветки автоматизация SHALL выполнять lint, проверку форматирования, типов, пользовательские smoke-проверки и production-сборку. Неуспешные проверки SHALL исключать публикацию соответствующего изменения.

#### Scenario: Ошибка проверки

- **WHEN** хотя бы одна обязательная проверка завершается ошибкой
- **THEN** изменение не публикуется и действующая версия сайта сохраняется

### Requirement: Автоматическая доставка

После успешных проверок обновление основной ветки SHALL автоматически публиковаться на выбранном VPS через GitHub Actions. Доступ к серверу SHALL задаваться секретами окружения доставки, не содержаться в публичных файлах и применяться только к выделенному сайту. Параллельные доставки SHALL не смешивать релизы.

#### Scenario: Успешное обновление

- **WHEN** обновление основной ветки прошло обязательные проверки
- **THEN** новая сборка публикуется без ручного копирования файлов и сайт показывает новую редакцию

#### Scenario: Ошибка передачи

- **WHEN** передача сборки на сервер завершается неуспешно
- **THEN** посетителю продолжает отдаваться предыдущая полная версия, без частично обновлённой страницы

### Requirement: Публичный HTTPS-адрес

Сайт SHALL открываться по HTTPS на подтверждённом домене экосистемы kolyach.me без регистрации. Запрос HTTP SHALL перенаправляться на HTTPS. Главная страница, изображения, стили, скрипты и резюме SHALL открываться без ошибок и смешанного содержимого.

#### Scenario: Проверка внешнего адреса

- **WHEN** посетитель открывает подтверждённый домен по HTTP
- **THEN** он перенаправляется на HTTPS с действительным сертификатом и получает читаемую страницу с рабочими ресурсами и PDF

### Requirement: Обновление и откат релиза

Процесс публикации SHALL позволять восстановить предыдущий рабочий релиз страницы и её ресурсов. При локальном варианте PDF SHALL храниться независимо от релизов: деплой, откат и очистка SHALL не изменять текущий документ. Внешний `resumeUrl` SHALL не требовать локального файла. После обновления страницы повторное открытие SHALL получать её актуальную редакцию с учётом повторной проверки кеша.

#### Scenario: Проверка отката

- **GIVEN** опубликовано минимум два релиза сайта, а PDF затем заменён независимо
- **WHEN** выполняется документированный откат
- **THEN** главная страница и её ресурсы возвращаются к предыдущей версии, а PDF остаётся в последней загруженной редакции

#### Scenario: Сохранность при деплое и очистке

- **GIVEN** автор заменил PDF непосредственно на сервере
- **WHEN** публикуется новый релиз сайта и удаляются старые каталоги релизов
- **THEN** файл PDF и его содержимое сохраняются без изменений, документ доступен по `/resume.pdf`

### Requirement: Независимая конфигурация контактов

Сборка и CI SHALL работать без реальных серверных переменных. На VPS скрипт SHALL формировать публичный JSON только из телефона, Telegram и `RESUME_URL`, проверять значения и заменять файл целиком. Пустой или отсутствующий `RESUME_URL` SHALL давать `/resume.pdf`; явно заданный некорректный адрес SHALL приводить к ошибке без замены прежнего JSON. Деплой, откат и очистка SHALL сохранять окружение и конфигурацию.

#### Scenario: Обновление без сборки

- **WHEN** автор меняет контактные переменные либо `RESUME_URL` на VPS и повторно запускает генерацию
- **THEN** новый JSON доступен по прежнему адресу, без запуска сборки или передачи значений в CI

#### Scenario: Неверное значение переменной

- **GIVEN** имеется действительная публичная конфигурация
- **WHEN** генерация получает отсутствующую обязательную контактную переменную или явно заданное некорректное значение
- **THEN** скрипт сообщает об ошибке без вывода реальных значений и не заменяет действительный файл

#### Scenario: Сохранность при публикации и откате

- **GIVEN** автор независимо обновил конфигурацию контактов
- **WHEN** выполняются публикация, очистка старых релизов или откат сайта
- **THEN** окружение и последняя конфигурация контактов сохраняются, остальные переменные окружения не появляются в публичном JSON

#### Scenario: Недопустимая ссылка резюме

- **GIVEN** существует действительная runtime-конфигурация
- **WHEN** генератор получает явно заданный `RESUME_URL`, отличный от `/resume.pdf` и абсолютного HTTPS-адреса
- **THEN** генерация завершается ошибкой, прежний JSON сохраняется и небезопасная ссылка не публикуется

### Requirement: Проверка готовности публичной версии

Первый релиз SHALL проходить проверку внешнего URL, мобильной компоновки, клавиатурной навигации, переключателя, ссылок, PDF и текста кейсов. Ввод сайта SHALL сохранять доступность других сайтов того же VPS.

#### Scenario: Приёмка

- **WHEN** завершена первая публикация
- **THEN** зафиксированы результаты проверки ширин 360, 768 и 1440 CSS-пикселей, увеличения текста до 200%, клавиатуры, ссылок и PDF, а также доступности соседних сайтов VPS
