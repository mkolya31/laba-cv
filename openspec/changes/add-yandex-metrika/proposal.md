# Proposal

## Why

Автору сайта нужно понимать, как нанимающий менеджер изучает страницу: какие блоки просматривает и по каким ссылкам переходит. Для этого подключается предоставленный счётчик Яндекс.Метрики 114281247 с Вебвизором.

## What Changes

- Подключить один счётчик ко всем страницам через общий layout с асинхронной загрузкой и параметрами из пользовательского кода, включая webvisor, clickmap и trackLinks.
- Добавить невидимый noscript-пиксель для посетителей без JavaScript.
- Проверить отсутствие повторной инициализации, сохранение работы интерфейса при недоступности Метрики и совместимость со статическим экспортом.
- Описать проверку счётчика и включения Вебвизора в кабинете Яндекса после публикации.
- Сохранить контекст вакансии: R&D-команда лаборатории кибербезопасности Сбера из исходного предложения; формального описания вакансии нет. Стек существующего проекта: Next.js App Router, React, TypeScript, статический экспорт и nginx на Ubuntu.
- MVP ограничен стандартной аналитикой страницы. Вне объёма: собственные цели и события, ecommerce-события, идентификация конкретного человека, аналитика содержимого внешнего PDF, новые страницы, изменение содержания резюме и отдельная система управления согласием.

## Capabilities

### New Capabilities

- `visitor-analytics`: подключение счётчика, запись поведения средствами Метрики, резервный пиксель и независимость интерфейса от аналитики.

### Modified Capabilities

Нет. Аналитика была явно исключена из начального build-resume-mvp как несогласованная; этот запрос отдельно согласует её добавление, не меняя требования к содержанию страницы.

## Impact

Затронуты src/app/layout.tsx, при необходимости отдельный компонент аналитики, браузерные проверки в tests/site.spec.ts и документация публикации. Добавляется внешний сетевой сервис mc.yandex.ru без новой npm-зависимости или серверного API. Внешний кабинет Метрики нужен для итоговой проверки записей; наличие счётчика не доказывает личность посетителя и не позволяет записывать содержимое внешнего PDF.
