# Design

## Context

Задача #23 содержит только точную замену подписи. В `src/app/page.tsx` ссылка первого экрана имеет класс `text-link`, `href="#cases"`, текст «Посмотреть, что я сделал» и вложенный `span` со стрелкой вниз. Раздел с `id="cases"` уже существует. Это обычная HTML-ссылка, доступная без клиентского JavaScript.

## Goals / Non-Goals

**Goals:**

- Показать согласованную подпись «Посмотреть доказательства» с сохранением перехода к кейсам.
- Сохранить оформление, стрелку, видимый фокус и адаптивность ссылки.

**Non-Goals:**

- Перестраивать первый экран, редактировать кейсы или заголовок их раздела.
- Менять зависимости, карусель, контакты, конфигурацию и процесс деплоя.

## Decisions

Заменить только текстовый узел в существующем элементе `a` в `src/app/page.tsx`. Сохранить `href`, класс и `span` со стрелкой. Отдельный компонент, обработчик клика и вынос строки в конфигурацию для одной подписи не нужны.

Использовать текущие Next.js App Router, React и TypeScript и статический экспорт: текст попадёт в HTML при сборке без дополнительной клиентской логики. Это укладывается в исходный бюджет 48 часов; сама правка занимает существенно меньше двух часов.

Проверить новую подпись и переход вручную, включая Tab/Enter и отключённый JavaScript. Новые автоматические тесты для обратимой замены строки не требуются; существующий `npm run check` проверяет общую интеграцию, включая production-сборку и браузерные smoke-тесты.

## Risks / Trade-offs

- Изменение длины подписи может повлиять на перенос: проверить ширины 360, 768 и 1440 CSS-пикселей и текст 200%.
- Случайная замена ссылки кнопкой нарушит переход без JavaScript: сохранить существующий HTML-элемент.
- Публикация проходит существующим путём через `develop` и `production`; предложение не запускает деплой. После штатной публикации проверить новую подпись на сайте.
